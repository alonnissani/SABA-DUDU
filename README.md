# סבא דודו — ארכיון הזיכרונות המשפחתי

אפליקציית הנצחה משפחתית פרטית: מקום אחד שבו בני המשפחה שומרים, צופים, מחפשים ומשתפים תמונות, סרטונים, הקלטות, סיפורים ומסמכים של סבא דודו.

האתר פרטי לחלוטין: אין הרשמה ציבורית, כל בן משפחה מצטרף דרך קישור הזמנה אישי, וכל קובץ מוגש רק אחרי התחברות.

## טכנולוגיה

- **Cloudflare Workers**: Worker אחד מגיש את האתר (React) ואת ה-API (`/api/*`, עם [Hono](https://hono.dev)).
- **Cloudflare D1**: בסיס הנתונים (SQLite). הסכמה ב-`migrations/`.
- **Cloudflare R2**: אחסון קובצי המקור. ה-bucket פרטי, וכל גישה עוברת דרך ה-Worker אחרי בדיקת התחברות.
- **React 19 + TypeScript + Vite**, RTL מלא, Mobile First, גופנים מקומיים (Frank Ruhl Libre, Assistant).
- **אימות**: סיסמאות מוצפנות ב-PBKDF2-SHA256 (WebCrypto), סשן בעוגיית `HttpOnly; Secure; SameSite=Lax` (במסד הנתונים נשמר רק ה-hash של הטוקן), הגנת CSRF לפי Origin, והגבלת ניסיונות התחברות.

### מבנה הפרויקט

```
worker/            ה-API: index.ts, routes/ (auth, items, uploads, files, search, admin), lib/
src/               ה-Frontend: screens/, components/, api/, styles/
shared/            טיפוסים וקבועים משותפים (קטגוריות, סוגי קבצים, מגבלות גודל)
migrations/        סכמת D1
public/            manifest, אייקונים, service worker
tests/api/         בדיקות API בתוך סביבת Workers (D1 + R2 מקומיים)
tests/e2e/         בדיקות דפדפן (Playwright): מובייל ומחשב
scripts/           ייצוא הארכיון, יצירת אייקונים
```

## פריסה ל-Cloudflare

> צריך חשבון Cloudflare. התוכנית החינמית מספיקה להתחלה. R2 חינמי עד 10GB, ואחר כך כ-0.015$ ל-GB בחודש.

אין צורך ליצור מראש את בסיס הנתונים ואת אחסון הקבצים. בפריסה הראשונה wrangler יוצר אותם אוטומטית לפי השמות שב-`wrangler.jsonc` (`saba-dudu-db`, `saba-dudu-media`), ובפריסות הבאות משתמש באותם משאבים. מבנה הטבלאות (migrations) מוחל אוטומטית בכל פריסה.

### אפשרות א׳: חיבור GitHub (Workers Builds), גם מהטלפון

1. ב-Cloudflare Dashboard: **Workers & Pages ← Create ← Import a repository** ← מתחברים ל-GitHub ובוחרים את `alonnissani/SABA-DUDU`. אם ה-Worker כבר מחובר: ה-Worker ← **Settings ← Builds**.
2. הגדרות ה-Build (בדיוק כך):

   | שדה | ערך |
   |---|---|
   | Production branch | `main` |
   | Build command | `npm run build` |
   | Deploy command | `npm run cf:deploy` |
   | Non-production branch deploy command | `npm run cf:preview` |
   | Root directory (Path) | ריק (שורש המאגר) |

   **למה זה חשוב:** `npm run build` מריץ את Vite, שבונה את האתר לתיקייה `dist/client` וכותב את הגדרות הפריסה הסופיות (`dist/saba_dudu/wrangler.json`, כולל תיקיית ה-assets). בלי שלב הבנייה wrangler לא מוצא את הקבצים הסטטיים, ולכן אין לשים `assets.directory` ב-`wrangler.jsonc`. `cf:deploy` פורס ומעדכן את טבלאות בסיס הנתונים. גם `cf:deploy` וגם `cf:preview` בונים בעצמם אם הבנייה לא רצה, כרשת ביטחון.
3. אחרי שהפריסה הראשונה מסתיימת: ב-Worker ← **Settings ← Variables and Secrets ← Add** ← סוג **Secret**, שם `SETUP_TOKEN`, ובערך מחרוזת ארוכה ואקראית. הקוד הזה נדרש רק פעם אחת, ליצירת המנהל הראשון, ולא נשמר בקוד.
4. נכנסים לכתובת `https://saba-dudu.<חשבון>.workers.dev`, יוצרים מנהל עם קוד ההקמה, מעלים את התמונה הראשית ושולחים הזמנות לבני המשפחה.

מעכשיו כל מיזוג ל-`main` יפרוס גרסה חדשה, וכל PR יקבל גרסת preview. הבדיקות האוטומטיות רצות ב-GitHub Actions על כל push (`.github/workflows/ci.yml`).

### אפשרות ב׳: מהמחשב

```bash
npx wrangler login
npm run deploy                       # build + deploy + migrations
npx wrangler secret put SETUP_TOKEN
```

### הפעלת הגיבוי הלילי (מומלץ מאוד)

1. יוצרים bucket שני: ב-Dashboard ← **R2 ← Create bucket** ← `saba-dudu-backup` (או `npx wrangler r2 bucket create saba-dudu-backup`).
2. מסירים את ההערה משורת `BACKUP` בקובץ `wrangler.jsonc` ופורסים שוב.

### דומיין משלכם (לא חובה)

ב-Dashboard ← ה-Worker ← **Settings ← Domains & Routes ← Add Custom Domain**.

## תמונות מתיקיית Google Drive משפחתית

האתר יכול להציג אוטומטית את התמונות מתיקייה משותפת ב-Google Drive. בני המשפחה מעלים לדרייב, והאתר מסתנכרן לבד פעם בשעה (Cron), או מיד בלחיצה על "סנכרן עכשיו".

- **אחסון:** התמונות נשארות בדרייב. ב-D1 נשמרים רק מזהה הקובץ, המידות ותאריך. אין עותק ב-R2.
- **הצגה:** הממוזערות (800px) והתצוגה הגדולה (2400px) מוגשות דרך ה-Worker מגוגל, עם מטמון בדפדפן בלבד. ההגשה דורשת התחברות לאתר.
- **הורדת המקור:** מפנה ישירות לגוגל.
- **תמונה שהוסרה מהדרייב:** מוסתרת מהאתר. היא חוזרת אם תוחזר לדרייב, ושום דבר בדרייב לא נמחק.
- **כשל זמני** (רשת, מכסה): הרשימה הקיימת לא משתנה.

**הגדרה חד-פעמית:**

1. **מפתח API ב-Google Cloud.** Google מחייבת מפתח גם לתיקייה ציבורית.
   1. ב-[console.cloud.google.com](https://console.cloud.google.com) יוצרים פרויקט.
   2. מפעילים את **Google Drive API** (APIs & Services ← Library).
   3. ב-Credentials יוצרים **API key**.
   4. ב-API restrictions בוחרים **Google Drive API** בלבד. ב-Application restrictions משאירים "None", כי הקריאות יוצאות מהשרת.
2. **סוד ב-Cloudflare.** בלוח הבקרה פותחים את ה-Worker ‏`saba-dudu-new` ← Settings ← Variables and Secrets ← Add, ומוסיפים:
   - Type: **Secret**
   - Name: `GOOGLE_DRIVE_API_KEY`
   - Value: המפתח

   לחלופין, משורת הפקודה: `npx wrangler secret put GOOGLE_DRIVE_API_KEY`.
3. **שיתוף התיקייה.** בדרייב משתפים את התיקייה עם "כל מי שיש לו את הקישור" (צפייה). מי שיעלה תמונות צריך הרשאת **עריכה** לתיקייה, וזה נקבע בדרייב, לא באתר.
4. **חיבור באתר.** באתר: הגדרות ← **חיבור Google Drive** ← מדביקים את קישור התיקייה ← "חיבור תיקייה".

## אבטחה ופרטיות

- **אין הרשמה ציבורית.** הצטרפות רק עם קישור הזמנה חד-פעמי ובעל תוקף. אפשר לנעול אותו לכתובת דוא״ל מסוימת.
- **רק מנהל יכול למחוק, לשחזר, לערוך**, לנהל משתמשים ולשנות הגדרות. הבדיקה נעשית בשרת על כל בקשה, גם אם מישהו עוקף את הממשק. מכוסה בבדיקות ב-`tests/api/archive.test.ts`.
- **מחיקה רכה:** פריט שנמחק עובר לסל המחזור (״הגדרות ← ניהול תכנים״). הרשומה והקבצים נשמרים, ואפשר לשחזר בכל עת.
- **קבצים:** נבדקים סוג וגודל, ותוכן הקובץ חייב להתאים לסוג המוצהר (בדיקת חתימת בתים). כל קובץ נשמר תחת מפתח ייחודי שנוצר בשרת (`onlyIf` מונע דריסה). המקור נשמר בלי דחיסה ובלי שינוי.
- **גישה לקבצים** רק דרך `/api/files/:id`, ורק למשתמש מחובר. ה-bucket לא חשוף. התמונה הראשית ומסך הפתיחה מוצגים רק לבני משפחה מחוברים.
- האתר מסומן `noindex`, וה-Service Worker לא שומר במטמון תכנים או קריאות API.
- אין סיסמאות או מפתחות בקוד. `SETUP_TOKEN` מוגדר כסוד (`wrangler secret put`), והקובץ `.dev.vars` מוחרג מ-git.

## גיבוי ושמירת הזיכרונות

| שכבה | מצב |
|---|---|
| קובצי מקור ב-R2 (אחסון קבוע, כפול אצל Cloudflare) | ✅ פעיל מהפריסה |

## הרחבות עתידיות

- **תמלול הקלטות:** ממלאים את טבלת `transcripts` (`text`, `segments_json`, `status='done'`), למשל עם Workers AI או שירות חיצוני, וקוראים ל-`reindexItem`. החיפוש יכלול את התמלול באופן אוטומטי.
- **חיפוש סמנטי:** אפשר להוסיף Cloudflare Vectorize לצד אינדקס ה-FTS הקיים (`worker/lib/search.ts`).
- **מאפיינים נוספים במסך הפתיחה:** המבנה `HeroTraits` (`shared/types.ts`) והרכיב `HeroTraitsView` מיועדים להרחבה.
- **קטגוריה חדשה:** מוסיפים ערך ל-`ITEM_KINDS` ב-`shared/constants.ts` ול-CHECK בסכמה.
